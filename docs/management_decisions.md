# Management decision checklist — Mitch and Michael

All decisions below are **pending**. Names identify the intended discussion audience,
not evidence of approval. Record the accountable decision owner/reviewer, written
policy, effective date, approved examples, impact and approval evidence privately.
Do not silently change existing rules to resolve a question.

| Decision | Current behavior / evidence needed |
|---|---|
| Missing repair duration | Original defaults can use one hour or found-related half-hour; approve blank/default policy and examples |
| Estimated labor rate | Original 12.50 rate remains; confirm purpose, currency, effective dates and whether any estimate should be described as actual |
| Estimated versus verified hours | Existing parsed/default RepairPersonHours stays numeric; define separate verified-hour evidence and effects on capacity visuals |
| Scheduled but incomplete service orders | Existing scheduled-OR-completed inclusion remains; define maintenance count/status interpretation |
| Service orders spanning months | Preserve current inclusion; decide report-month versus completion/schedule/calendar views and comparison scope |
| Offline equipment in inventory totals | Offline is a status, not deletion; choose inclusive/filtered counts and effective-date policy |
| Unknown building/room | Retain raw location with visible unresolved status; approve mapping owner/aliases and Building_Dim key contract |
| Missing monthly report / zero activity | Current completeness needs all three supported nonempty candidates; agree explicit zero-activity evidence and escalation, not fabricated files |
| Corrections after approval/publication | Current correction token only selects a local candidate revision; require fresh business approval bound to exact corrected hashes and rollback evidence |
| Preventive/corrective maintenance | Source tags are metadata, not an approved classifier; define taxonomy/labeled examples, overlap/conflict policy and review ownership |
| Remaining financial grain/precision | Confirm unequal nonzero repair field/subtotal meaning, null/rounding policy and month-only parts/labor uses before model migration |
| Long-term support | Name support/IT/model/data owners and backups; approve local retention, recovery drill, release/signing and employee handoff/training |

Arithmetic reconciliation and successful import do not supply these decisions.
The future approval record must distinguish reviewer authority, selected revision,
UTC timestamp and evidence. This checklist does not create that record.
